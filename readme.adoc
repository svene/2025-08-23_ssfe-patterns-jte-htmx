= Hypermedia Patterns — Plain JTE

Spring Boot app: the *plain JTE* take on the Hypermedia / htmx pattern course
— no View Components, just JTE's own template-composition mechanisms
(`@template` calls, `Content` parameters). Sibling of the JTE-VC, Thymeleaf,
Qute and Hono variants — same "people / page" demos, expressed with plain JTE
templates.

== Usage

- Start the application with the `dev` profile:
  `mvn spring-boot:run -Dspring-boot.run.profiles=dev` (or run `Application`
  from the IDE with the `dev` profile active).
+
This variant has no `jte-maven-plugin`, so there are no precompiled
templates — the `dev` profile turns on `gg.jte.developmentMode`, which
compiles `.jte` templates on demand from `src/main/jte`. Without it, the app
fails to start (`gg.jte.developmentMode` or `gg.jte.usePrecompiledTemplates`
must be set).
- Open http://localhost:8080/ — the landing page lists every demo, grouped by
  module.

== Modules

Numbering matches the other variants so demos line up across the family;
`s02` is intentionally skipped — it is only used by variants with a
View-Components or JSX concept, which this plain-JTE variant deliberately
does not have.

[cols="1,3"]
|===
| `s00` | Landing page — the card menu.
| `s01` | Simple Pages — basic template, fragment include, fragment parameters, content/slot parameter, nested fragments.
| `s03` | Page Patterns — content page, content page taking a request parameter, custom page taking a parameter, MPA example (two pages sharing a nav layout).
| `s04` | UI Patterns — parent/child (slot content passed down), forwarder (a fragment delegates to another).
| `s05` | htmx Patterns — URL components (a button `hx-get`s a fragment endpoint; htmx swaps the result in).
|===

=== Pattern: Template-Injection (Content-Page pattern, `s03d01`/`s03d02`)

A page has the passive role: it is injected, via a JTE `Content` parameter,
into a reusable layout.

[source,jte]
.s03pages/d01.jte
----
@template.fragments.layout(
  title = "Content Page",
  content = @`
    <h1 class="title">Content Page</h1>
`
)
----

[source,jte]
.fragments/layout.jte
----
@import gg.jte.Content

@param String title
@param Content content

<!DOCTYPE html>
<html lang="en">
@template.fragments.pagehead(title = title)
<body>
<div class="container mt-1">
    <div class="p-1 mt-1">
        ${content}
    </div>
</div>
</body>
</html>
----

=== Pattern: Template-Inclusion (Custom-Page pattern, `s03d03`)

A page has the active role: it builds the whole document itself and only
reuses the small `pagehead` fragment via a plain `@template` call (no
`Content` parameter).

[source,jte]
.s03pages/d03.jte (excerpt)
----
<!DOCTYPE html>
<html lang="en">
@template.fragments.pagehead(title = "Custom Page")
<body>
    <h1 class="title">Custom Page with Param says: ${greeting}</h1>
</body>
</html>
----

NOTE: JTE does not allow unclosed tags in a template, so `pagehead` cannot
itself open `<body>` for the caller to close. The workaround is to put the
enclosing tag in the consumer, as done here. For non-simple cases it is
better to use the Template-Injection pattern (JTE `Content` parameters)
instead.

== Conventions

- *htmx 4*, vendored at `src/main/resources/static/js/htmx.org/4.0.0/htmx.js`
  (no webjar).
- *Bulma 1.0.4*, vendored at `src/main/resources/static/css/bulma/1.0.4/`.
- Templates under `src/main/jte/`; shared fragments (`layout`, `pagehead`,
  `maincard`, …) in `src/main/jte/fragments/`.
- One controller per module (`s0XController`), URL constants on the
  controller, routes `/s0N/d0N`.
